2. WinDbg Kurulumu ve İlk Ayarlar

2.1 WinDbg'yi kurun

  1. Windows Start menüsünü açın ve Microsoft Store yazın.
  2. Store'da WinDbg veya WinDbg Preview aratın. Microsoft imzalı uygulamayı seçin.
  3. Get / Install düğmesine basın.
  4. Kurulum bitince Start menüsünden WinDbg'yi açın. Açılışta File, Home, Open dump file ve Attach to a process seçeneklerini görmelisiniz.
  5. Klasik Debugging Tools for Windows kuruluysa windbg.exe de kullanılabilir; menü isimleri biraz farklı olabilir.

2.2 Symbol path

6. Process Bulma ve WinDbg'ye Attach

6.1 Process ve PID nedir?

Process çalışan program örneğidir. Host modunda uygulamayı çalıştıran ana process genellikle dotnet.exe, PID ise Windows'un o process'e verdiği sayısal kimliktir.

Get-Process dotnet | Format-Table Id,ProcessName,Path,StartTime
Get-CimInstance Win32_Process -Filter "Name = 'dotnet.exe'" | Select-Object ProcessId,CommandLine
Id   ProcessName Path
---- ----------- ----
1234 dotnet       C:\Program Files\dotnet\dotnet.exe

CommandLine içinde RestApi.dll veya RestApi.csproj görülmeli.

Task Manager yöntemi: Ctrl+Shift+Esc → Details → dotnet.exe satırı → sağ tık Go to details. Command line sütunu görünmüyorsa başlık satırına sağ tıklayın → Select columns → Command line.

6.2 WinDbg GUI

  1. Start menüsünden WinDbg açın.
  2. File > Attach to Process seçin. Bazı sürümlerde Home ekranındaki Attach to a process kartı bulunur.
  3. Process listesinde doğru PID'yi seçin. Command line içinde RestApi yazan process'i tercih edin.
  4. Attach düğmesine basın.
  5. Debugger process'i durdurur. Bu normaldir; Command penceresinde break state görünür.
  6. İlk iş g yazıp Enter'a basarak uygulamayı devam ettirin.

7. Breakpoint Türleri

7.1 Source breakpoint

En güvenilir başlangıç yöntemi, Visual Studio/VS Code'da gerçek satırın soluna breakpoint koyup PDB ile eşleştirmektir. WinDbg GUI'de Debug > Breakpoints > New Breakpoint veya Ctrl+B kullanılabilir; source dosya/satır seçin.

bp RestApi!RestApi.Controllers.ProductController.GetAll
bl
bc 0
be 0
bd 0
0 e Disable/Enable durumu olan breakpoint listesi
Method adı çözümlenmezse pending breakpoint görülebilir.

7.2 Function / conditional breakpoint

bp RestApi!RestApi.Controllers.AuthController.Login
bp /1 RestApi!RestApi.Controllers.NoteController.GetAll
bp /w "@$tpid == 1234" RestApi!RestApi.Controllers.ProductController.GetAll

/1 ilk hit'ten sonra silinecek geçici breakpoint örneğidir. Conditional breakpoint sözdizimi WinDbg sürümüne ve native/managed bağlama göre değişebilir; source window üzerindeki koşul alanı daha güvenlidir.

7.3 Exception breakpoint

sxe clr
sxe av
sxe eh
bl

sxe exception oluştuğunda first chance break ister. Gürültü çoksa yalnızca deney için sxd clr ile devam davranışına dönebilirsiniz. C# DivideByZeroException için SOS ile exception nesnesini kontrol edeceğiz.

7.4 Module, address ve data breakpoint

bm RestApi!*Product*
lm m RestApi
ba e 1 RestApi!SomeAddress

Managed object field için klasik native data breakpoint doğrudan uygun değildir. Managed field değişimini izlemek için source breakpoint veya debugger'ın managed data breakpoint desteğini kullanın; WinDbg sürümünde desteklenmiyorsa bu özellik demonstrasyon olarak kalır.

10. Gerçek Exception Lab: NoteController.GetAll

Bu proje sürümündeki gerçek hata: NoteController.GetAll() içinde int i = 1; int ii = i / 0; vardır. Bu endpoint kasıtlı olarak DivideByZeroException üretir. Dokümanda demonstrasyon değildir; repository'de mevcut gerçek koddur.

Adım adım

  1. Note role'lü token ile WinDbg'ye attach olun.
  2. sxe clr veya source breakpoint'i NoteController.GetAll'a koyun.
  3. g yazın.
  4. GET /api/Note gönderin.
  5. Breakpoint'te dv ile notes, i değişkenini görün.
  6. F10 ile int ii = i / 0 satırını çalıştırın. Exception break etkinse debugger burada durur.
  7. !pe, !clrstack, k çalıştırın.
  8. Development'ta detaylı hata, Production'da GlobalExceptionHandler tarafından error ID içeren 500 JSON beklenir.

12. Thread Analizi

Process, uygulamanın tamamıdır; thread ise process içinde kod çalıştıran yürütme akışıdır. ASP.NET Core aynı anda gelen request'leri ThreadPool üzerinde işleyebilir. Bu projede manuel Thread veya Task.Run yoktur.

~
~*
!threads
~5s
!clrstack
Managed thread listesi ve her thread için state.
~5s ile 5 numaralı native thread seçilir.
!clrstack o thread'in managed stack'ini gösterir.

Kontrollü concurrency

Bu projede global rate limiter 10 saniyede 4 request kabul eder. Birden fazla PowerShell request'i göndererek farklı request thread'lerini gözlemleyebilirsiniz:

1..4 | ForEach-Object { Start-Job { Invoke-WebRequest http://localhost:5120/health -UseBasicParsing } }
Get-Job | Receive-Job -Wait

Thread ID'lerin request sayısıyla birebir eşleşmesi beklenmez; ThreadPool thread reuse yapar. Bu yüzden “her request yeni thread” varsayımı yanlıştır.

13. Async / Await Gerçeği ve Demonstrasyon Sınırı

Controller action'ları bu repository sürümünde senkron IActionResult döner; EF çağrıları SaveChanges, ToList, Find ve FirstOrDefault şeklindedir. Async görünen kod yalnız middleware Invoke metotları ve JWT event'idir.

Bu proje sürümünde async controller/EF senaryosu bulunmadığı için aşağıdaki snippet yalnız WinDbg kavramını göstermek içindir; gerçek RestApi kodu gibi yorumlamayın.
public async Task<IActionResult> Example()
{
    var item = await SomeAsyncOperation();
    return Ok(item);
}

Async state machine'de breakpoint await öncesi ve sonrası farklı stack gösterebilir. !clrstack içinde compiler-generated state machine isimleri görülebilir. Gerçek projede bu akışı izlemek için önce async EF refactor gerekir.

16. Deadlock ve Lock

Mevcut RestApi kodunda lock veya manuel synchronization kullanılmıyor; gerçek deadlock senaryosu yoktur. Bu bölüm demonstrasyon kapsamındadır.

~* k
!threads
!syncblk

Klasik SOS sürümlerinde !syncblk monitor sahiplerini/bekleyenleri gösterebilir. Modern runtime'da komut çıktısı farklı olabilir. Aynı lock üzerinde “Owner” ve “Waiting” thread'leri bulun, sonra her thread için ~Ns ve !clrstack çalıştırın.

Bir thread'i yalnızca stack'te bekliyor gördüğünüz için deadlock ilan etmeyin. İki veya daha fazla thread'in birbirinin tuttuğu kaynağı beklediğini kanıtlayın.

17. Dump Alma ve Dump Açma

17.1 ProcDump kurulumu

  1. Microsoft Sysinternals ProcDump sayfasından ProcDump ZIP'i indirin.
  2. Örneğin C:\Tools\ProcDump klasörüne açın.
  3. PowerShell'i bu klasörde açın.
$pid = (Get-CimInstance Win32_Process -Filter "Name='dotnet.exe'" | Where-Object CommandLine -like '*RestApi*').ProcessId
.\procdump.exe -accepteula -ma $pid C:\Temp\RestApi-full.dmp
Writing dump file ...
Dump complete

-ma full dump'tır; managed heap ve process state daha kapsamlıdır fakat dosya büyüktür ve hassas veri içerebilir.

17.2 Crash/exception dump

.\procdump.exe -accepteula -e -ma -w dotnet.exe C:\Temp\RestApi-crash.dmp

-e exception olaylarını izler, -w process'i bekler. Production dump'larında dosya izinlerini ve secret redaction politikasını uygulayın.

17.3 WinDbg'de dump açma

  1. WinDbg → File > Open dump file veya Ctrl+D.
  2. C:\Temp\RestApi-full.dmp seçin.
  3. Command penceresinde .symfix, .reload /f, !clrstack çalıştırın.
  4. !pe ile exception, !threads ile thread, !dumpheap -stat ile heap inceleyin.

22. “Neden Olmadı?” Rehberi

Breakpoint pending veya tetiklenmiyor
  1. Doğru dotnet PID'si mi?
  2. Get-CimInstance Win32_Process command line'da RestApi var mı?
  3. RestApi.dll doğru module mü: lm m RestApi?
  4. PDB/source path doğru mu?
  5. Gerçekten endpoint çağrıldı mı?
  6. Role auth nedeniyle controller'a hiç girilmemiş olabilir mi?
  7. Release optimization local değişkeni kaldırmış olabilir mi?
SOS / !clrstack tanınmıyor

Process managed olmayabilir, yanlış architecture kullanıyor olabilirsiniz veya CLR module henüz yüklenmemiştir. lm m coreclr, .loadby sos coreclr, !soshelp deneyin. WinDbg x64 ile .NET x64 runtime kullanın.

Attach Access Denied

WinDbg'yi yönetici olarak açın, aynı kullanıcıyı kullanın, Visual Studio'nun process'i pause etmediğini kontrol edin. Protected/system process'e attach etmeyin.

API 401/403 veriyor ve breakpoint'e düşmüyor

Authorization controller'dan önce çalışır. Login token role claim'i Product veya Note olmalı. Token header'ı Authorization: Bearer ... biçiminde gönderin.

Database connection failed

Host modunda docker compose ps postgres, pg_isready ve localhost:15432 kontrol edin. Host appsettings localhost:15432, Docker env ise postgres:5432 olmalıdır. Host process'e Docker DNS adı vermeyin.

HTTPS redirect / port uyarısı

HTTP profiliyle http://localhost:5120 kullanın. HTTPS profili https://localhost:7209 ve HTTP 5120 açar. Development certificate için dotnet dev-certs https --trust çalıştırın.

Dump açıldı ama source yok

Dump alınan build'in PDB'si gerekir. Aynı commit/build çıktısını koruyun; .sympath, .srcpath, .reload /f çalıştırın.

26. Projede Bulunmayan Özellikler İçin Açık Not

Aşağıdaki başlıklar istenen genel WinDbg eğitim kapsamının parçasıdır, ancak bu repository sürümünde gerçek implementasyonları yoktur. Bu nedenle örnekleri gerçek RestApi davranışı gibi kullanmayın:

  • Unit/integration test projesi
  • Async controller/EF query, CancellationToken

  • HttpClient ile dış API
  • Cache/Redis
  • Manuel lock, monitor, deadlock

Bu konular için kontrollü demo kodu eklemek mümkündür; ancak mevcut production kodunu değiştirmeden önce ayrı branch veya geçici çalışma kopyası kullanın.

Bu dokümandaki PID, address, MethodTable, thread ID, token ve dump path değerleri örnektir. Bir komutun örnek çıktısını birebir beklemeyin; önemli olan aynı kavramların ve frame'lerin görünmesidir.
